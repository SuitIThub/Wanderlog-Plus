# Tabelog für Restaurants — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Der Server holt für Restaurants (Bestand und neue) Tabelog-Daten über Apify und speichert sie am Ort; die App zeigt eine Tabelog-Karte, einen Score-Chip und öffnet den Eintrag möglichst in der mehrsprachigen Tabelog-App.

**Architecture:** `Place.tabelog` (shared). Server: `TabelogSource` (Apify, zweistufig), `TabelogNames` (Google ja-Name + Präfektur), `TabelogMatch` (≤ 300 m + Name), `TabelogSummary` (Textmodell), `TabelogSweeper` (alle 15 min + auf Anstoß, max. 20). App: `TabelogCard`, `tabelogTargets`, Score-Chip.

**Tech Stack:** Kotlin, Ktor, kotlinx.serialization, java.net.http, Jetpack Compose, JUnit/Robolectric.

**Spec:** `docs/superpowers/specs/2026-11-11-tabelog-design.md`

## Global Constraints

- Version **0.63.0**, versionCode 82, CHANGELOG `## 0.63.0`, README-Abschnitt.
- Neue Felder mit Default; Server-Logs ohne Inhalte (nur Zähler/Klassennamen).
- Apify: `run-sync-get-dataset-items?timeout=240`, HTTP-Timeout 270 s, Token `WLP_APIFY_TOKEN`, Actor `WLP_APIFY_TABELOG_ACTOR` (Standard `huggable_quote~tabelog-scraper`).
- Suche: `includeReviews:false`, `maxRestaurants:3`; Bewertungen: `startUrls`, `maxReviewsPerRestaurant:3`, `sortBy:"newest"`.
- Treffer nur ≤ 300 m und ähnlicher Name; höchstens 20 Restaurants pro Durchlauf; Intervall 15 min, erster Lauf 1 min nach Start.
- Restaurant = gespeicherter Ort (nicht DROPPED) mit Kategorie FOOD oder NIGHTLIFE und Koordinaten ≠ 0.
- Tabelog-App-Paket `com.kakaku.tabelog.tourists`.
- Ausführung: JDK 17 (`JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-17.0.17.10-hotspot`).

## Review Focus

1. Apify liefert Zahlen mal als String, mal als Zahl, Koordinaten fehlen → Treffer ohne Koordinaten werden nie gewählt; kein Crash → Test Task 2.
2. Zwei Filialen 200 m auseinander („一蘭 渋谷店“ / „一蘭 渋谷スペイン坂店“) → die nähere mit passendem Namen → Test Task 3.
3. Apify-Kontingent leer / 402 / Netzfehler mitten im Durchlauf → Durchlauf endet, nichts geschrieben, nächster Lauf versucht erneut → Test Task 4.
4. Handschuss mit einer Nicht-Tabelog-URL → App lehnt ab, Server ignoriert sie (nur `https://tabelog.com/`) → Tests Task 4 und 5.
5. Zwei gespeicherte Orte zeigen auf denselben `Place` → nur ein Abruf → Test Task 4.

### Task 4: Zusammenfassung, Sweeper, Route, Wiring

**Files:** Create `server/src/main/kotlin/de/wanderlogplus/server/tabelog/TabelogSummary.kt`, `TabelogSweeper.kt`; Modify `ServerConfig.kt` (`apifyTabelogActor`), `Main.kt`, `Application.kt` (Services-Feld `tabelog: TabelogSweeper?`, Route `POST /api/tabelog/refresh` → 503 `tabelog_not_configured` ohne Sweeper, sonst 202 und `sweeper.kick()`); Tests `TabelogSummaryTest.kt`, `TabelogSweeperTest.kt`

**Interfaces — Produces:**
- `class TabelogSummary(model: ChatModel) { fun summarize(reviews: List<TabelogReview>): String }` — leer bei leerer Liste oder Fehler.
